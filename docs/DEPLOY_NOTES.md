# 배포 준비물 노트 (Render 같은 클라우드에 백엔드를 올릴 때)

이번 실습에서는 **실제 배포를 하지 않았습니다.** 앱은 내 컴퓨터에서 실행하고, 저장소(DB)만 Supabase 클라우드입니다.
아래는 나중에 백엔드를 Render 같은 서비스에 올릴 때 필요한 준비물입니다.

DB 저장 위치를 바꾸는 것(SQLite → Supabase)과 앱을 인터넷에 공개하는 것은 별개입니다.

## 1. 코드 보관 위치
- GitHub 저장소: https://github.com/skygaul/my-todo (`main` 브랜치)
- 호스팅 서비스가 이 저장소를 읽어 가므로, 코드는 GitHub에 있어야 합니다.
- `.env`는 저장소에 올리지 않습니다. 값은 호스팅 서비스의 환경변수 화면에 따로 입력합니다.

## 2. 서비스 종류와 명령
| 항목 | 값 |
|---|---|
| 종류 | Web Service (Node) |
| Node 버전 | 20 이상 (`package.json`의 `engines`) |
| Build Command | `npm install` |
| Start Command | `npm start` (= `node server/index.js`) |
| 상태 확인 경로 | `/` (200) |

## 3. 환경변수 (호스팅 서비스 화면에 입력)
| 이름 | 값 | 비고 |
|---|---|---|
| `SUPABASE_URL` | `https://<프로젝트>.supabase.co` | 대시보드 페이지 주소가 아니라 Project URL |
| `SUPABASE_ANON_KEY` | 공개용(publishable/anon) 키 | `secret`/`service_role` 키는 넣지 않음. 넣으면 서버가 시작을 거부함 |
| `HOST` | `0.0.0.0` | 기본값 `127.0.0.1`이면 외부에서 접속할 수 없음 |
| `NODE_ENV` | `production` | 로그인 쿠키에 `Secure`가 붙음. HTTPS에서만 로그인이 유지됨 |
| `PORT` | (호스팅 서비스가 자동 지정) | 코드가 `PORT`를 읽음 |

## 4. Supabase 쪽에서 확인할 것
- `supabase/schema.sql`이 이미 적용되어 있어야 합니다. (표, RLS 정책, 권한)
- Authentication의 URL 설정(Site URL)을 배포 주소로 맞춥니다. 이메일 확인 링크가 이 주소를 씁니다.
- 지금은 테스트를 위해 "Confirm email"을 꺼 두었습니다. **공개 배포 전에는 켜는 것을 권장**합니다. 켜면 이메일 인증을 받아야 로그인됩니다.
- 무료 플랜의 한도(저장 용량, 월간 사용자 수)와 일정 기간 미사용 시 일시정지 여부, 백업 정책은 가입 시점의 공식 가격/문서 페이지에서 확인합니다.

## 5. 공개하기 전에 점검할 위험
- 로그인이 없던 로컬용과 달리, 배포하면 **누구나 가입할 수 있습니다.** 가입 제한이 필요한지 정합니다.
- 비밀번호 정책(길이 등)과 로그인 시도 제한은 Supabase Auth 설정에 따릅니다. 우리 코드는 8자 이상만 확인합니다.
- HTTPS가 필수입니다. (쿠키 `Secure`)
- 키는 코드에 적지 않고 환경변수로만 둡니다. 코드를 GitHub에 올려도 키가 새지 않습니다.
- 비밀번호 재설정 화면은 아직 없습니다.

## 6. 배포 후 확인하는 방법
1. 배포 주소(예: `https://<서비스>.onrender.com`)에 접속해 로그인 화면이 뜨는지 봅니다.
2. 로그인 전 `GET /api/todos`가 **401**인지 봅니다.
3. 가입 → 로그인 → 할 일 추가 → 새로고침 후에도 남는지 봅니다.
4. Supabase Table Editor의 `todos`에 행이 쌓였는지 봅니다.
5. 같은 Supabase를 쓰므로, 내 컴퓨터에서 `scripts/verify-rls.js`를 실행해 RLS를 다시 확인합니다.

## 7. 알려진 제약 (공식 문서에서 확인할 것)
- 무료 웹 서비스는 한동안 요청이 없으면 잠들어, 첫 요청이 느릴 수 있습니다.
- 서버를 여러 대로 늘려도 로그인 상태는 쿠키 안의 토큰이라 서버끼리 공유할 필요는 없습니다.
